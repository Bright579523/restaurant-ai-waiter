📄 เอกสารอธิบาย Vector Embedding Pipeline (สร้างไฟล์แคชเวกเตอร์ความหมายอาหาร)
================================================================================
วิชา / โครงงาน: ReDi School Final Project - Swagat AI Waiter
จัดทำโดย: Bright
ไฟล์สคริปต์หลักที่เกี่ยวข้อง: build_embeddings.py
ผลลัพธ์ที่ได้: menu_embeddings.pkl (ไฟล์แคชเวกเตอร์และ DataFrame)
================================================================================

ขั้นตอนถัดมาหลังจากได้ตารางข้อมูลที่สะอาดและมีโครงสร้างชัดเจน (swagat_menu.csv)
คือขั้นตอนการแปลงข้อความธรรมดา (Text) ให้กลายเป็นรหัสเวกเตอร์ตัวเลข (Vector Embeddings)
เพื่อใช้เป็นดัชนีสำหรับให้ AI ประมวลผลและค้นหาตามนัยหรือความหมายเชิงภาษา (Semantic Search)

--------------------------------------------------------------------------------
1. ความหมายของ Vector Embedding ในระบบนี้
--------------------------------------------------------------------------------
- โดยปกติ คอมพิวเตอร์ไม่เข้าใจความหมายของภาษาคน เช่น ไม่รู้ว่า "Lamm" (แกะ) มีความหมายใกล้เคียงกับ
  คำว่า "Mutton" หรือคำสั่งว่า "อยากกินเนื้อ"
- Vector Embedding คือกระบวนการส่งข้อความเมนูอาหารผ่านโครงข่ายประสาทเทียม (Deep Learning Model)
  เพื่อถอดรหัสออกมาเป็นกลุ่มตัวเลขในระบบพิกัดหลายมิติ
- ยิ่งคำพูดหรือเมนูอาหารมีทิศทางความหมายหรือรสชาติใกล้กัน พิกัดตัวเลขในมิติเหล่านั้นจะยิ่งใกล้กัน
  ทำให้เราหาความสัมพันธ์เชิงความหมายได้ แม้จะพิมพ์ค้นหาคนละภาษาหรือใช้คำไม่ตรงกับในเมนูก็ตาม

--------------------------------------------------------------------------------
2. โครงสร้างการทำงานของ build_embeddings.py
--------------------------------------------------------------------------------
สคริปต์รันสร้างเวกเตอร์ทำงานเป็นขั้นตอนดังนี้:

2.1 การนำเข้าตารางข้อมูล (Load Dataset)
    - โหลดไฟล์ตาราง 'swagat_menu.csv' ที่ได้จากการทำ Data Pipeline ในรูป Pandas DataFrame

2.2 การดึงดัชนีคำค้น (Extract Search Texts)
    - ดึงข้อมูลจากคอลัมน์ 'search_text' ซึ่งเป็นประโยครวบยอดของอาหารแต่ละจาน
    - โครงสร้างข้อความค้นหา: "Name: [ชื่อ] | Category: [หมวดหมู่] | Description: [คำอธิบายเยอรมัน] | Allergens: [สารแพ้]"
    - การรวมข้อมูลทั้งหมดไว้ในจุดเดียวทำให้อีเวนต์การค้นหารอบด้าน ครอบคลุมทั้งชื่อและส่วนผสมหลัก

2.3 การโหลดโมเดลภาษา (Load SentenceTransformer)
    - โหลดโมเดล 'paraphrase-multilingual-MiniLM-L12-v2' ด้วยไลบรารี sentence-transformers
    - เหตุผลที่เลือกใช้โมเดลนี้:
      * Multilingual (รองรับหลายภาษา): สามารถจับคู่ความหมายระหว่างภาษาไทย อังกฤษ และเยอรมันได้อย่างสมบูรณ์
      * Lightweight (น้ำหนักเบา): มีขนาดประมาณ 118 MB รันในเครื่องฝั่งผู้ใช้งานได้เร็วและไม่ต้องใช้อินเทอร์เน็ต
      * Output Dimension (ขนาดมิติพิกัด): 384 มิติ (มิติข้อมูลกำลังเหมาะสม ไม่กว้างจนทำงานช้า)

2.4 การสร้างเวกเตอร์แบบแบ่งกลุ่ม (Batch Encoding)
    - ทำการส่งประโยคคำค้น (search_text) ทั้ง 157 เมนูเข้าโมเดลเพื่อประมวลผลพร้อมกันในแบบแบ่งกลุ่ม
      (Batch size = 32)
    - ผลลัพธ์ที่ได้จากการถอดรหัสของโมเดลจะเป็น NumPy Matrix ขนาด [157, 384]
      (อาหาร 157 เมนู โดยแต่ละเมนูถูกแสดงแทนด้วยพิกัดตัวเลข 384 ตัว)

2.5 การแพ็กไฟล์และทำแคช (Pickle Caching)
    - เพื่อไม่ให้ตัวแอปพลิเคชันต้องดาวน์โหลดหรือประมวลผลโมเดลเวกเตอร์เมนูทั้ง 157 เมนูใหม่ในทุกครั้ง
      ที่เปิดโปรแกรมหรือพิมพ์คุยแชต (ซึ่งจะทำให้ช้าและกินทรัพยากรมาก)
    - สคริปต์จะนำ DataFrame ดั้งเดิม มารวมเข้ากับ Matrix เวกเตอร์ที่เพิ่งรันเสร็จ
      และเก็บข้อมูลชื่อโมเดลเอาไว้ด้วยกันในแบบ Dictionary
    - จากนั้นทำการเขียนเซฟอ็อบเจกต์ในหน่วยความจำออกมาในรูปแบบไบนารีไฟล์ชื่อ 'menu_embeddings.pkl'
      (ด้วยฟังก์ชัน pickle.dump)

--------------------------------------------------------------------------------
3. สรุปผลลัพธ์และความสำคัญต่อระบบ RAG
--------------------------------------------------------------------------------
- ไฟล์ menu_embeddings.pkl ทำหน้าที่เสมือน "สมองฐานข้อมูลคำศัพท์ล่วงหน้า (Offline Indexed Vector Database)"
- เมื่อนำไปใช้ในขั้นตอนออนไลน์ (เช่น ตอนรัน streamlit app.py และ search_engine.py)
  ระบบจะเพียงแค่โหลดไฟล์ .pkl ขนาด 280 KB นี้ขึ้นมาในหน่วยความจำเครื่อง
- เมื่อลูกค้าพิมพ์คำค้นเข้ามา ระบบจะรันโมเดลแปลงพิกัดเฉพาะคำถามของลูกค้าข้อความเดียว (ซึ่งใช้เวลาน้อยมาก)
  แล้วไปประเมินความใกล้เคียงกับเวกเตอร์ 157 ตัวที่แคชไว้อยู่แล้วได้ทันที
- ส่งผลให้ระบบ RAG ค้นหาข้อมูลได้เร็วระดับมิลลิวินาที (Real-time Search) โดยไม่ต้องพึ่งระบบฐานข้อมูลภายนอก
