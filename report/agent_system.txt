================================================================================
📄 เอกสารอธิบายระบบ AI Agent และกลไก RAG (Orchestrator, Intent Parser & Generator)
================================================================================
วิชา / โครงงาน: ReDi School Final Project - ReDi AI Waiter
จัดทำโดย: Bright
ไฟล์สคริปต์หลักที่เกี่ยวข้อง: agent.py และ search_engine.py
ผลลัพธ์ที่ได้: คลาสระบบตอบแชตและแนะนำอาหารอัตโนมัติ (ReDiAIAgent)
================================================================================

หลังจากสร้างฐานข้อมูลเมนู (CSV) และเวกเตอร์แคช (Pickle) เรียบร้อยแล้ว
ขั้นตอนต่อไปคือ "AI Agent" ซึ่งทำหน้าที่เสมือนเป็นสมองหลักในการประมวลผลและการโต้ตอบ (Orchestration)
โดยทำหน้าที่เป็นตัวกลางรับแชตลูกค้า -> คิดและแปลงคำสั่ง -> ค้นหาอาหาร -> เรียบเรียงคำตอบ RAG

ระบบการทำงานของ AI Agent ในไฟล์ agent.py และ search_engine.py มีรายละเอียดการทำงานดังนี้:

--------------------------------------------------------------------------------
1. ส่วนประกอบหลักของ AI Agent
--------------------------------------------------------------------------------
AI Agent ของเราถูกออกแบบขึ้นโดยใช้ไลบรารี Pydantic เพื่อควบคุมความถูกต้องของข้อมูล
และใช้ Groq API (เชื่อมต่อไปยังโมเดล Llama 3.3 70B) มีส่วนประกอบหลัก 3 ส่วนดังนี้:

1.1 ตัวกรองแบบมีโครงสร้าง (Pydantic Schemas)
    - คลาส 'SearchFilters': กำหนดเงื่อนไขที่ลูกค้าอาจร้องขอ เช่น vegetarian (เจหรือไม่),
      max_price (งบสูงสุด), contains_ingredients (ส่วนผสมที่ต้องการ),
      exclude_ingredients (ส่วนผสมที่เลี่ยง), และ exclude_allergens (สารก่อภูมิแพ้ที่ห้ามมี)
    - คลาส 'ParsedIntent': ใช้ห่อหุ้ม SearchFilters คู่กับคอลัมน์ search_query (คำค้นหาส่วนผสมเชิงลึก)

1.2 หัวใจการกรองและค้นหา (MenuSearchEngine)
    - คลาสจาก search_engine.py ที่ทำหน้าที่เป็นตัวกรองข้อมูลแบบลูกผสม (Hybrid Search Engine):
      * ขั้นที่ 1 (Metadata Filtering): ใช้ NumPy/Pandas กรองตารางเอาเมนูที่ไม่ตรงเงื่อนไขของลูกค้าออกไปก่อน
        เช่น ลูกค้าเป็นมังสวิรัติและมีงบ 15 ยูโร ระบบจะลบรายการที่มีเนื้อสัตว์และราคาเกิน 15 ออกทันที
      * ขั้นที่ 2 (Semantic Similarity): นำรายการที่ผ่านด่านกรองมาเปรียบเทียบพิกัดเวกเตอร์ด้วยวิธี
        Cosine Similarity เพื่อจัดอันดับเมนูอาหารที่เหมาะสมที่สุดขึ้นมาแสดง (Top-K)

1.3 พนักงานเสิร์ฟสมองกล (ReDiAIAgent)
    - ตัวควบคุมหลักของ RAG Pipeline ที่ดูแลตรรกะการทำแชตในทุกรอบของการคุยโต้ตอบ (Chat Loop)

--------------------------------------------------------------------------------
2. ขั้นตอนการประมวลผลแบบละเอียดต่อ 1 ข้อความแชต (RAG Pipeline)
--------------------------------------------------------------------------------
เมื่อผู้ใช้พิมพ์คำถามคุยกับบอต (เช่น: "ขอแกงแกะเผ็ด ๆ ราคาไม่เกิน 20 ยูโร ไม่เอาแป้งสาลี")
ระบบจะทำงานตามลำดับ 3 ขั้นตอนดังนี้:

[ขั้นที่ 1: การแกะเจตนาลูกค้า (Intent Parsing)]
- AI Agent ส่งคำถามของลูกค้าพร้อม System Prompt พิเศษไปที่โมเดล Llama 3.3 ผ่าน Groq API
- โหมดที่ใช้: JSON Mode (โมเดลจะบังคับผลลัพธ์ให้ออกมาเป็นโครงสร้างข้อมูล JSON เท่านั้น)
- หน้าที่ของโมเดล: แปลงภาษาเขียนของมนุษย์ให้กลายเป็นก้อนข้อมูลคีย์ลอจิก เช่น:
  * แปลงคำว่า "แกงแกะเผ็ด ๆ" ➔ search_query: "spicy lamb curry", contains_ingredients: ["lamb"]
  * แปลงคำว่า "ราคาไม่เกิน 20 ยูโร" ➔ max_price: 20.0
  * แปลงคำว่า "ไม่เอาแป้งสาลี" ➔ exclude_allergens: ["a"] (รหัส 'a' ย่อมาจาก Gluten/แป้งสาลี)

[ขั้นที่ 2: การค้นหาแบบสองระดับ (Hybrid Retrieval)]
- AI Agent นำคีย์และตัวกรองที่แกะได้จากขั้นที่ 1 ส่งให้คลาส MenuSearchEngine
- ตัวค้นหาทำการกรองทางคณิตศาสตร์ทันที (ลบรายการที่มีสารก่อภูมิแพ้ 'a', ลบรายการราคา > 20,
  และตรวจสอบว่ามีป้ายกำกับแกะ)
- จากนั้น นำเวกเตอร์คำถามของลูกค้าไปทำ Cosine Similarity วัดมุมกับเวกเตอร์อาหารที่ผ่านด่านกรอง
- คืนค่ารายการอาหารที่ดีที่สุด 3 ลำดับแรกกลับมาให้ AI Agent (เรียกว่า RAG Context)

[ขั้นที่ 3: การร่างคำตอบแนะนำสไตล์บริกร (Response Generation)]
- AI Agent รวบรวมเมนูที่ค้นหาได้ (พร้อมชื่อ, คำอธิบายภาษาเยอรมัน, ราคา, และสารแพ้)
  มาเขียนประกบเข้ากับคำถามของลูกค้า เพื่อส่งกลับไปถามโมเดล Llama 3.3 อีกครั้ง
- System Prompt สั่งการหลัก:
  * "ให้ทำหน้าที่เป็นบริกรผู้สุภาพของร้านอาหาร ReDi แนะนำเมนูอาหารที่ดึงมาจากขั้นตอนค้นหาเท่านั้น"
  * "ต้องอธิบายให้กระจ่างว่าทำไมรายการเหล่านี้ถึงเหมาะสมกับโภชนาการหรืองบประมาณของเขา"
  * "เขียนโต้ตอบในภาษาเดียวกับที่ผู้ใช้พิมพ์ทักเข้ามา" (เช่น ถามภาษาไทย บอตจะตอบเป็นภาษาไทย)
- โมเดลประมวลผลและส่งเนื้อความแชตกลับไปแสดงผลบนหน้าจอแอปพลิเคชัน Streamlit

--------------------------------------------------------------------------------
3. ระบบสำรองเมื่อไม่มี API Key (Rule-based Fallback Parser)
--------------------------------------------------------------------------------
- ในกรณีที่ระบบไม่มีอินเทอร์เน็ต หรือผู้ใช้งานไม่ได้ตั้งค่าคีย์ความปลอดภัย (GROQ_API_KEY) ในไฟล์ .env
- AI Agent จะสลับการทำงานไปใช้ระบบสำรองโดยอัตโนมัติ (Heuristic Mock Parser):
  * ใช้ฟังก์ชันจับคำหลัก (Regex/Keyword detection) ใน Python เช่น หาคำว่า "veg", "chicken", "under [ตัวเลข]"
  * กรองตารางแบบปกติ และคืนผลลัพธ์ในรูปแบบโครงสร้างรายการเมนูเบื้องต้น เพื่อให้หน้ากากแอปพลิเคชัน
    ยังคงทำงานค้นหาอาหารแนะนำได้โดยไม่เกิดปัญหาโปรแกรมแครช (Crash)

================================================================================

แต่ยังคงความถูกต้องของเมนูและโภชนาการส่วนบุคคลได้อย่างปลอดภัยและตรงความจริง
